# 스캔 영역: 오른쪽 쏠림 수정 + 사용자 지정 영역 계획

작성일: 2026-10-14
대상: 설정 > 스캔 영역 (`screens/ScanRegionSelectionScreen.js`), 스캔 화면 영역 표시·판정 (`components/ScanRegionOverlay.js`, `components/ScanReticle.js`, `components/NativeQRScanner/index.js`)

## 0. 지금 구조 (2026-10-14 확인)

- 모드는 `full | center | band` 셋. 저장 키 `scanRegionMode` (AsyncStorage).
- `ScanRegionOverlay`가 **자기 크기를 재서** 사각형(dp)을 계산하고 `onRegionChange`로 스캔 화면에 알린다.
  - center: 짧은 쪽 70% 정사각, band: 가로 85% × 세로 22%. 둘 다 `x = (width - w) / 2`로 가운데.
- 그리는 곳 두 군데: 바깥 어둡게 + 흰 테두리(`ScanRegionOverlay`), 조준 코너(`ScanReticle`, 같은 사각형을 받음).
- 판정: `NativeQRScanner` worklet이 코드의 센서 좌표를 `computeHighlights(..., 'cover')`로 화면 dp로 바꾼 뒤, **코드 중심이 사각형 안이면** 통과.
- 에뮬레이터(1080×2400)에서 가로 띠를 켜 보니 **그림은 정확히 가운데**였다 (좌 65 / 우 65 dp 대칭).

## 1단계. 오른쪽 쏠림 원인 확인 (0.5일)

> 2026-10-14 갱신: 신고된 쏠림은 **설정 화면의 미리보기 아이콘**이었고 고쳤다(`dcb71d6`, 테두리 두께를 빼지 않고 계산). 스캔 화면 자체는 에뮬레이터에서 가운데였다. 아래는 사용자 지정 영역을 만들 때 폴드 기기에서 함께 확인할 항목으로 남긴다.

그림이 쏠리는지, **인식되는 위치(판정)가** 쏠리는지에 따라 원인이 다르다. 실기기(Z Fold7)에서 둘 다 본다.

| 증상 | 의심 원인 | 확인 방법 |
|---|---|---|
| 테두리 자체가 오른쪽에 그려짐 | 오버레이 부모가 화면보다 넓음 (폴드 펼침·창 크기 변경 후 `onLayout` 갱신 누락, 화면 회전) | 개발자 옵션에 오버레이가 잰 `width×height`와 사각형 `x,y,w,h`를 글자로 표시 → 화면 폭과 비교 |
| 테두리는 가운데인데, 왼쪽에 둔 코드는 안 읽히고 오른쪽 밖 코드가 읽힘 | 센서 좌표 → 화면 좌표 변환(`computeHighlights` cover 계산)이 기기 화면비(Fold 커버 21:9, 내부 화면 거의 정사각)나 센서 방향과 안 맞음 | 이미 있는 개발자 옵션 **"스캔 영역 판정 표시"**를 켜면 영역 밖으로 판정된 코드에 빨간 테두리가 그려진다 → 빨간 테두리가 실제 코드 위치보다 왼쪽에 있으면 변환 문제 |
| 둘 다 정상인데 조준 코너만 쏠림 | `ScanReticle`의 레이아웃이 오버레이와 다른 부모 크기를 잼 | 같은 디버그 글자에 리티클 레이아웃 크기도 표시 |

- 수정 방향(원인별)
  - 레이아웃: 사각형을 `onLayout` 한 번이 아니라 `useWindowDimensions` 변화(폴드 펼침·접힘, 회전)에도 다시 계산. 오버레이와 리티클이 **같은 측정값**을 쓰게 사각형 계산을 스캔 화면 한 곳으로 올린다.
  - 판정 변환: 카메라 뷰의 실제 미리보기 크기(프레임 화면비 × cover)로 오프셋을 계산하도록 `computeHighlights` 호출에 넘기는 레이아웃을 카메라 뷰 자신의 `onLayout` 값으로 통일. Fold 커버(1080×2520)·내부(2184×1968)·일반(1080×2400) 세 경우로 계산 테스트(`scripts/test-scan-region.js` 새로 — 센서 좌표 → dp 변환을 순수 함수로 빼서).
- 끝 조건: 세 화면비에서 테두리 가운데 정렬 + 영역 안 코드만 통과(디버그 빨간 테두리가 실제 코드 위치와 일치).

## 2단계. 사용자 지정 영역 — 저장 형식과 계산 (0.5일)

- 새 모드 `custom`. 저장 키 `scanRegionCustom` = `{ "w": 0.8, "h": 0.25, "cx": 0.5, "cy": 0.5 }`.
- **저장은 화면 비율(0~1), 보여 주기·입력은 dp(픽셀)**로 한다.
  - 이유: 같은 폰이라도 폴드 접힘/펼침, 회전, 다른 기기로 백업 복원하면 화면 크기가 바뀐다. 픽셀로 저장하면 영역이 화면 밖으로 나가거나 한쪽에 쏠린다(지금 신고된 증상과 같은 종류).
  - 화면에서는 "가로 300 · 세로 120 · 왼쪽 45 · 위 380 (dp)"처럼 픽셀로 보이고, 고치면 그 화면 크기 기준 비율로 바꿔 저장한다.
- 중심(cx, cy) 기준 저장 → "가운데 맞춤"이 값 하나로 끝나고, 화면 크기가 바뀌어도 가운데에 머문다.
- `computeScanRegion(mode, width, height, custom)`에 `custom` 분기 추가: 비율 → dp, 그다음 **화면 안으로 자르기**(최소 크기 80×48 dp, 가장자리 0 이상).
- iCloud 동기화 허용 키(`services/iCloudService.js`의 `SYNC_ALLOWED_PREFIXES`)에 `scanRegionCustom` 추가.

## 3단계. 영역 편집 화면 (2일)

설정 > 스캔 영역 > **"직접 지정"** 행(4번째 선택지) → 새 화면 `app/scan-region-editor.tsx` (`screens/ScanRegionEditorScreen.js`).

화면 구성 (위 → 아래):
1. **미리보기**: 실제 카메라 화면 위에 영역 사각형(스캔 화면과 같은 `ScanRegionOverlay` 그대로). 화면 비율은 스캔 화면과 같게(탭바 높이만큼 뺀 크기) — 여기서 맞춘 게 스캔 화면과 픽셀 단위로 같아야 한다.
   - 사각형 **끌어서 이동**, 네 모서리 **끌어서 크기 조절** (react-native-gesture-handler, 이미 설치됨). 끌 때 가운데선(가로·세로)에 붙는 자석 8dp.
2. **숫자 입력** (dp, 정수):
   - 크기: 가로 · 세로
   - 위치: 왼쪽 · 위 · 오른쪽 · 아래 (왼쪽을 고치면 오른쪽이 자동으로 바뀜 = 크기 유지하고 이동)
   - 각 칸 옆 −/+ 버튼(1dp, 길게 누르면 10dp씩 빠르게)
   - 범위 밖 값은 입력이 끝날 때 잘라 맞추고 짧게 안내("화면 밖이라 340으로 맞췄어요")
3. **빠른 버튼**: 가운데 맞춤 · 가로 꽉 채우기 · 정사각형 · 처음 값(띠 모양으로)
4. **저장**(주 버튼) / 취소. 저장하면 모드가 `custom`으로 바뀌고 스캔 화면에 바로 반영.

- 미리보기에 카메라를 켜는 이유: 실제로 비춰 보며 맞추는 게 숫자보다 빠르다. 카메라 권한이 없으면 회색 바탕 미리보기로 대신.
- 설정 목록의 아이콘: 지금 세 모드처럼 작은 폰 모양 안에 사용자 사각형을 비율대로 그린다.

## 4단계. 판정·네이티브 연동 (1일)

- JS 판정(코드 중심이 사각형 안)은 그대로 쓰면 custom도 동작한다 — 1단계 변환 수정이 전제.
- 네이티브 보조 판독 위치를 영역 중심으로: 지금 반전 재시도(Android 가운데 80%), 데이터 매트릭스 2배 판독(Android·iOS 가운데 60%)은 **화면 가운데 고정**이라, 영역을 한쪽으로 옮기면 보조 판독이 엉뚱한 곳을 본다.
  - 스캔 화면 → `extraOptions`로 영역(센서 좌표 비율)을 네이티브에 넘기고, 크롭 중심·크기를 영역에 맞춘다 (`docs/PLAN_SCAN_RECOGNITION.md` 6단계와 같은 작업이라 여기서 같이 한다).
  - 화면 dp → 센서 좌표 비율 변환은 1단계에서 뺀 순수 함수의 역함수.
- iOS: Vision `regionOfInterest`(왼쪽 아래 원점 비율)로도 넘겨 처리량을 줄인다.

## 5단계. 마무리 (0.5일)

- 다국어 문구 5개 언어: 직접 지정, 가로/세로/왼쪽/위/오른쪽/아래, 가운데 맞춤, 가로 꽉 채우기, 정사각형, 처음 값, 잘라 맞춤 안내.
- 확인: 에뮬레이터 스크린샷(일반·폴드 비율 AVD 두 개), 실기기에서 영역을 왼쪽 위/오른쪽 아래로 옮겨 그 안 코드만 읽히는지, 폴드 접고 펴도 영역이 같은 자리(비율)에 있는지.
- 개발자 옵션 "스캔 영역 판정 표시"는 유지(현장 문제 볼 때 씀).

## 결정이 필요한 것

1. 쏠림이 **테두리 그림**인지 **인식 위치**인지 — 스캔 화면 스크린샷(가운데 사각형 모드, 코드 하나 비춘 상태)이 있으면 1단계가 빨라진다.
2. 입력 단위를 dp(화면 점)로 할지 실제 기기 픽셀로 할지. 권장: **dp** — 기기마다 픽셀 밀도가 달라 같은 숫자가 다른 크기가 되는 걸 피한다. (Z Fold7 커버 화면은 1dp ≈ 2.6px)
3. 편집 화면에서 카메라를 켤지(권장) / 회색 미리보기만 둘지.
